## 1. 導入

動作条件: **macOS 14.2 以上**（`CATapDescription` を使ってアプリの音を取り込むため）

```bash
brew tap pasrom/meeting-transcriber
brew trust --tap pasrom/meeting-transcriber   # Homebrew 6.0 以降で必要な場合がある
brew install --cask meeting-transcriber
```

- 起動するとメニューバーに常駐する
- 初回の文字起こしで、モデルが自動でダウンロードされる（WhisperKit は約 1GB）。**ダウンロードのときだけ通信が発生する**。HF トークンは不要
- バージョンとリリース日は「設定 → Advanced」で確認する（meeting-transcriber の README からは最新版の日付を確かめられなかった）

## 2. 権限

| 権限 | 第一案での要否 | 理由 |
|---|---|---|
| マイク | **必要** | 自分の声を録る |
| アプリの音の取り込み | 必要（個別の許可は不要。録音中は紫の点が出る） | 相手の声を録る |
| 画面収録 | 不要（任意） | 会議名の検出が正確になるだけ |
| アクセシビリティ | 不要（任意） | Teams の参加者名とミュート状態を読む。第一案では相手同士を区別しないので使わない |

権限は最小限から始め、検出がうまくいかないときだけ画面収録を足す。

## 3. 設定

| タブ | 項目 | 設定値 | 理由 |
|---|---|---|---|
| General | Apps to Watch | **Teams と Browser** だけにチェック | 検証対象だけを録る |
| General | 更新の確認 | オフ | 検証中の通信を減らす |
| General | record-only mode | オフ（文字起こしまで行う） | — |
| Audio | マイク | 実際に使うマイク | — |
| Audio | echo cancellation | **オフ（初期値）のまま** | まずヘッドホンだけで音漏れを防げるか確かめる |
| Transcribe | ASR エンジン | **WhisperKit** | Parakeet は欧州25言語のみで、日本語に対応していない |
| Transcribe | language | **日本語に固定** | 言語の自動判定による誤りを避ける。選択肢の表記は未確認 |
| Transcribe | model | まず初期値、次に大きいモデル | モデルの大きさと精度・速度の関係を見る |
| Transcribe | Live caption overlay | 試すときだけオン | **試作段階の機能**。会議中の字幕を確かめる |
| Speakers | mic speaker name | 自分の名前（仮名でよい） | 文字起こしで「自分」の発言に付くラベル |
| Output | **LLM provider** | **none** | 文字起こしを LLM に送らない。会議の内容には社名・氏名・案件などが含まれるため。Claude Code CLI も選ばない |
| Output | Save raw transcript separately | オン（初期値） | 生の文字起こしを評価に使う |

> meeting-transcriber の README の動作要件には「Claude Code CLI か OpenAI 互換の API が必要」とありますが、設定で LLM provider を **none** にできると書かれています。none にすると議事録（.md）は作られず、文字起こし（.txt）だけが出力されます。

## 4. 検証用の会議の作り方

- 自分と協力者2人以上で、**テスト用の Teams 会議と Meet 会議** を開く（相手が複数人の状況を作るため）
- 参加者は、**公開されている文章**（青空文庫やニュース記事など）を順番に読み上げる。正解の文章が手元にあるので、文字起こしの誤りを数えられる
- 各回3〜5分程度。自然な会話（相づちや言い直しを含む）の回も1つ入れる
- Meet は **会議専用のブラウザ**（Chromium 系。例: Chrome）で開く。meeting-transcriber は Chromium 系ブラウザの Meet を検出する

## 5. 確かめること

### 確認1: Teams・Meet の音を取り込めるか

| 手順 | 合格の目安 |
|---|---|
| Teams の会議を始め、自動で録音が始まるか見る | 録音が始まり、紫の点が出る |
| Meet の会議（専用ブラウザ）で同じことをする | 同上 |
| 会議後の文字起こしに、相手の発言が入っているか | 相手の発言が「自分」以外のラベルで入っている |
| **Meet の会議中に、同じブラウザの別のタブで動画を流す** | 動画の音声が文字起こしに入るかを記録する（入る場合は「Meet 専用ブラウザでは他の音を出さない」運用が必要になる） |

うまく録れないとき: 設定の「Diagnostics → Verbose Audio Logging」をオンにして同じ操作をし、Console.app で `com.meetingtranscriber.audiotap` のログ（音量・デバイス）を見る。

### 確認2: ヘッドホンで音漏れを防げるか

| 手順 | 合格の目安 |
|---|---|
| ヘッドホンをして会議し、自分のトラックの文字起こしを見る | **相手の発言が自分のラベルで出てこない** |
| （比較）スピーカーで同じことをする | 相手の発言が自分のラベルで重複して出るかを記録する |

- リリースノートによると、v0.8.0 でスピーカーからの音漏れを検出する機能が入っている。スピーカーで音漏れしたときに警告が出るかも見ておく
- 音漏れするなら、Audio タブの echo cancellation をオンにして再度試す

### 確認3: 日本語の精度

| 手順 | 記録すること |
|---|---|
| 読み上げた文章と文字起こしを比べる | 文字誤り率（CER）。下の手順で測る |
| 自然な会話の回を読む | 意味が取れるか、議事録の材料として使えるか（主観で ○△×） |
| 人名・社名・専門用語 | 誤りが多ければ、Transcribe タブの custom vocabulary に登録して再度試す |
| 処理時間 | 会議の長さに対して、文字起こしが終わるまでの時間 |
| モデルの大きさ | 初期値と大きいモデルで、CER と処理時間を比べる |

CER の測り方（例）。読み上げた文章を `ref.txt`、その区間の文字起こしを `hyp.txt` に保存し、空白・改行・句読点を除いて比べる:

```bash
python3 -m venv .venv && .venv/bin/pip install jiwer
.venv/bin/python - <<'EOF'
import re, jiwer
norm = lambda s: re.sub(r"[\s、。，．,.!?！？「」]", "", s)
ref = norm(open("ref.txt").read()); hyp = norm(open("hyp.txt").read())
print(f"CER: {jiwer.cer(ref, hyp):.1%}")
EOF
```

### おまけ: 会議中の字幕と、相手同士の区別

第一案の合否には使いませんが、ついでに見ておくと次の判断に役立ちます。

- **Live caption overlay**（試作段階）を表示し、日本語の字幕が出るか、遅れはどのくらいかを記録する
- 文字起こしで、相手の2人が別のラベルに分かれているかを見る（話者分離の精度の目安）

## 7. 後片付け

- 文字起こしの保存先: `~/Library/Application Support/MeetingTranscriber/protocols/`
- 録音ファイルの保存先と保存期間は meeting-transcriber の README に書かれていない（未確認）。アプリの設定で確認する
- 検証が終わったら、録音と文字起こしを削除する。PC の外（クラウドストレージや外部の AI サービス）には出さない
- アンインストール:

```bash
brew uninstall --cask meeting-transcriber
rm -rf ~/Library/Application\ Support/MeetingTranscriber   # 中身を確認してから実行する
```

- 「設定 → プライバシーとセキュリティ」で、付与した権限（マイクなど）も外す
